Taskosaur Architecture & Application Workflow

Derived from https://github.com/taskosaur/taskosaur · Next.js workspace + NestJS API + Prisma/Postgres + Redis/Bull queues + Socket.IO realtime

Source evidence checked

  • Root workspace package.json: frontend + backend workspaces
  • backend/src/app.module.ts: API modules and global JwtAuthGuard
  • backend/prisma/schema.prisma: 44 persistent models
  • frontend/src/lib/api.ts and socket.ts: HTTP + realtime client paths

Core domains

  • Organizations, workspaces, projects, members, roles
  • Tasks, subtasks, dependencies, comments, attachments, ranks
  • Sprints, workflows/statuses, labels, time entries, Gantt/calendar
  • Inbox/email, notifications, activity logs, settings, AI conversations

Operational dependencies

  • PostgreSQL for primary relational state via Prisma
  • Redis/BullMQ for async jobs; adapter/fallback queue exists
  • Socket.IO /events for room-scoped updates
  • S3-compatible storage optional for media/attachments
